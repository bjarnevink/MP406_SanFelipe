# SFINCS flood model – San Felipe (Yucatán, Mexico)

This repository contains the Jupyter notebooks to build a quadtree [SFINCS](https://sfincs.readthedocs.io) flood model for the town of San Felipe (Yucatán, Mexico) with [HydroMT-SFINCS](https://deltares.github.io/hydromt_sfincs/), and to set up a factorial design (2³ = 8 scenario runs) with this model.

The model is a street-level flood model for the town, on a rotated quadtree grid that is refined over the LiDAR extent (40 m → 5 m) while the lagoon and the sea stay coarse to keep computation times low.

## Contents

| File / folder | Description |
|---|---|
| `Build_model.ipynb` | Builds the complete SFINCS model (grid, elevation, mask, buildings, roughness, infiltration, boundary conditions, wind and precipitation). Water level boundary from the GTSM reanalysis (Norte event, 4–7 February 2024) or from El Cuyo AWAC measurements (validation run, 8–11 November 2025) |
| `Build_model_StatAnalysis.ipynb` | Builds the same base model and generates the 8 scenario runs of the factorial design with the synthetic drivers P (precipitation), S (storm surge) and I (infiltration of the built-up area). After SFINCS has been run, it also extracts the flood scores Y1–Y4 |
| `data/` | Input files read by the notebooks (see [Data](#data)) |

The factorial analysis itself (effects of P, S and I on Y1–Y4) is done in a separate notebook that reads the `Y1.csv` … `Y4.csv` files written by `Build_model_StatAnalysis.ipynb`.

Running the notebooks only **builds** the models. Running SFINCS and post-processing are not part of the notebooks.

## Getting started

1. Clone this repository.
2. Create a Python environment with the packages below.
3. Download the input files from Zenodo (see [Data](#data)) and put them in `data/`.
4. Open a notebook and run it from top to bottom (*Restart kernel and run all*).
5. Run SFINCS on the model folder that the notebook writes (`sfincs_san_felipe_qtr/` for `Build_model`, `sfincs_runs/run_<name>/` for `Build_model_StatAnalysis`).

### Python packages

- `hydromt-sfincs` (a version with quadtree support)
- `geopandas`, `shapely`, `pyproj`, `rasterio`
- `xarray`, `numpy`, `pandas`
- `cfgrib` (with ECMWF `eccodes`) to read the ERA5 GRIB files
- `matplotlib`

The basemap plot in section 5 needs an internet connection. To run the models you also need the SFINCS executable.

## Model settings in short

- **CRS:** EPSG:32616 (UTM zone 16N) for all model data
- **Time:** all times and forcing are in UTC
- **Grid:** domain rotated 35° around its centre, 40 m coarsest cell, 3 refinement levels (5 m) over the LiDAR extent
- **Mean sea level** is at −0.5 m in the model elevation datum; this value is used as initial water level and as offset on the boundary water levels
- **Buildings** are represented as raised grid cells (+3.5 m)
- **Switched off:** advection, Coriolis, SnapWave

## Factorial design (`Build_model_StatAnalysis.ipynb`)

| Driver | Lower bound (−) | Upper bound (+) |
|---|---|---|
| P precipitation (peak intensity of a Gaussian event) | 0.0 mm/h | 13.4 mm/h (about 306 mm in 3 days) |
| S storm surge (peak, on top of a synthetic tide) | 0.0 m | 0.87 m |
| I infiltration rate of the built-up class | 0 mm/h | 50 mm/h |

The 8 runs are written to `sfincs_runs/run_<name>/`, so make sure there is enough disk space (about 8 times the size of one model). After SFINCS has been run in every folder, the last section of the notebook computes four flood scores from `sfincs_his.nc`:

| Score | Definition |
|---|---|
| Y1 | Percentage of observation points that are flooded [%] |
| Y2 | Mean maximum depth over the flooded points [m] |
| Y3 | Mean inundation duration over the flooded points [h] |
| Y4 | 95th percentile of the maximum depth over the flooded points [m] |

Finally, use the `CompoundFloodingAnalysis.ipynb` notebook to execute the factorial design analysis.
